## 1. Goal & acceptance criteria
1. **Chips**: suggestion chips render ONLY on `/app/chat/new` (above the composer). Not on `/app`, not in the bubble panel, not on `/app/chat/[id]`. Composer placeholder everywhere reads "Ask Finch anything about your operation…" (design 1a) — grep and replace every "Ask Vyso" string under `components/platform/**` and `app/app/**` (marketing untouched).
2. **Card cap**: the Brief's "Today's brief" feed shows at most **5** cards. Ordering ("most imperative"): `status='new'` before `in_progress`; then `rand_impact desc nulls last`; then `created_at desc`. If open non-informational findings ≤ 5 → show all. If > 5 → show the top **4** + a fifth **overflow card**: "You have {N−4} other items that need your attention." with a "View the full briefing →" action to `/app?view=all`. Informational (doc_watch) cards keep their own band and never count. The greeting keeps the TRUE total ("{N} things need your attention"). `/app?view=all` = **Full briefing**: every open finding, grouped by agent (Price Watch, Debtors, Stock, then Read overnight), same card component, a "← Back to today's brief" link, rail highlights "Today's brief". History view unchanged.
3. **Access**: the Brief is for owners/admins only. Define ONE server-side predicate `canSeeBrief(role)` = `role === 'owner' || role === 'admin'` in `lib/platform/access.ts` (and reuse it wherever `canSeeMoney` is computed — they are the same rule today; keep the two names, one implementation, comment why). For a user without it: `/app` (all views) and `/app/finding/*` **redirect** to their first unlocked module (`railModules(...)[0].href`, else `/app/settings`) — never a 403 page; the rail hides "Today's brief" and "History" (chats + New chat + Under the hood remain — chats are useful and every money tool is already gated); the layout does NOT build the findings prelude or findings-based suggestions for them (`briefChatContext` only when `canSeeBrief`); `GlobalChatDock` on `/app`… n/a (redirected). `MobileDrawer` mirrors the rail. Digest cron unaffected (it emails the configured address). RLS is untouched — this is UI/route gating on top of the existing money gate; say so in the code comment.
4. Gates green: `npx tsc --noEmit`, `npm test` (376 + new), `npm run build`, lint errors ≤ 50.

## 3. Edge cases
- Exactly 5 open → 5 cards, no overflow. 6 → 4 + "2 other items". Overflow card is not dismissible.
- Dismissing a card on the Brief refreshes and the next-ranked finding slides in (existing `router.refresh()`).
- `view=all` for a non-admin → same redirect. Unknown `view` value → today's brief.
- Role missing/null → treated as no access (fail closed).
- Member with zero unlocked modules → `/app/settings`.
- The redirect must not loop: `/app/settings` and module pages never redirect back to `/app`.
